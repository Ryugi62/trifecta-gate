Trifecta Gate

An AI assistant that reads your files, reads strangers' mail and can send email can be talked into leaking.

Trifecta Gate finds that combination in an agent's tools and blocks the send when the address came from a stranger, not from you.

How the gate decides

The gate never asks a model whether text looks malicious. It checks where an outgoing message is going and where that address came from.

  1. You named it: the address or site appears in your request or your allowlist. Allowed.
  2. A stranger named it, and private data is in play: the agent has read your files or mail in this run. Blocked, and the agent is told to ask you.
  3. A stranger named it, nothing private read yet: nothing to leak. Allowed, so browsing still works.
  4. Private text in the outgoing call: a 12-character piece of a private result heading to an address you did not name. Blocked, even if the earlier checks were bypassed.
What it does not catch

If you name the recipient yourself, the gate lets the message go even if the agent was tricked into adding extra data. Replies to someone who emailed you look exactly like an attack, so they need one confirmation from you. The tool classifier is keyword rules; it can mislabel unusual tools, which is why you can override labels.
